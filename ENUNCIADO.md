# Proyecto Final — Data Engineering (CoderHouse 101990)

## Actividad

Formato de entrega: **Google Docs** que centralice y evidencie todo el pipeline end-to-end.

## Secciones requeridas

El documento debe contener, como mínimo, las siguientes secciones claramente estructuradas:

1. **Arquitectura y justificación técnica**: descripción del diseño del sistema, decisiones tomadas y trade-offs.
2. **Infraestructura**: definición de servicios (puede incluir fragmentos de docker-compose o manifiestos de Kubernetes como anexos dentro del documento).
3. **Orquestación (Airflow)**: descripción de DAGs, lógica de ejecución y capturas o evidencias de funcionamiento.
4. **Transformaciones (dbt)**: modelos, tests definidos y explicación del flujo de datos.
5. **Procesamiento distribuido (PySpark)**: descripción de jobs, lógica implementada y casos de uso.
6. **Datos de ejemplo**: muestras utilizadas y explicación de su estructura.
7. **Pruebas automatizadas**: estrategia de testing y ejemplos representativos.
8. **CI/CD**: descripción del pipeline (aunque no esté automatizado), incluyendo etapas, validaciones y flujo esperado.
9. **Observabilidad**: configuración conceptual o aplicada de monitoreo (Prometheus, Grafana), incluyendo métricas, logs y dashboards (con capturas si aplica).
10. **Runbook**: guía operativa para ejecutar, mantener y resolver problemas del pipeline.
11. **Documentación técnica**: explicaciones adicionales necesarias para comprender el sistema.
12. **Guía de demo**: pasos detallados para reproducir el funcionamiento o enlace a video demostrativo.
13. **Evidencia de ejecución**: capturas, logs o resultados que demuestren que el pipeline funciona correctamente.
14. **Calidad del código**: fragmentos relevantes comentados y explicación de buenas prácticas aplicadas.

## Criterios de Evaluación

La entrega será evaluada en base a:

| Criterio | Descripción |
|----------|-------------|
| Funcionalidad | Correcta ejecución del pipeline |
| Calidad técnica | Claridad, buenas prácticas, modularidad |
| Observabilidad | Capacidad de monitoreo y diagnóstico |
| Testing | Cobertura y relevancia de pruebas |
| Documentación | Claridad, completitud, orden |
| Justificación arquitectónica | Coherencia y fundamentos de diseño |

## Entregable

Google Docs que contenga todo el desarrollo del proyecto final correctamente ordenado.
